## Что уже запускается автоматически

В Планировщике Windows созданы:

1. `Academy BEPS - Website collection`: ежедневный сбор должен завершиться минимум за 50 минут до слотов 09:00, 13:00 и 17:00 Europe/Moscow; run-collector.ps1 собирает сайты и формирует локальный дайджест. Повторы при аварийном завершении: до трёх с интервалом 10 минут.
2. `Academy BEPS - Local portal`: запускается при входе пользователя в Windows; открывает локальную страницу http://127.0.0.1:8765 .
3. `Academy BEPS - Auto Publisher`: запускается автономно 3 раза в день строго в **09:00, 13:00, 17:00 Europe/Moscow** и доставляет только заранее проверенный пакет Antigravity `approved\YYYY-MM-DD_HH00_editorial.json`. Перед отправкой выполняет dry-run, а успех фиксирует только после 10 Telegram-receipts и immutable run record. Он не отбирает сырые кандидаты и не выдаёт их за проверенные новости.
4. `Academy BEPS - Watchdog`: запускается каждые 15 минут; проверяет портал, реальные коды задач, delivery receipts, run records, свежесть сбора и покрытие источников. Редакционный чат периодически не опрашивает. Логи и итоговый статус: `runtime-logs\watchdog.log`, `runtime-logs\auto-publisher-status.json`, `runtime-logs\health-status.json`.

Обе задачи работают в вошедшем сеансе пользователя vakhi. Выключенный/спящий компьютер новости не собирает. Сбор с сайтов не требует работающего Codex или Antigravity. Подготовка и отправка редакционного выпуска требуют работающего Antigravity с настроенным в нём расписанием.

Автоматический сбор **не отправляет сообщения** и не превращает кандидатов в проверенные новости. Antigravity должен проверить факты и подготовить пакет до 08:50, 12:50 или 16:50; Windows-задача доставит его в ближайший дедлайн. Полный контракт и критерий успеха: `ANTIGRAVITY_CONTROL.md`. Не дублировать сайт-сбор собственным одновременным daily_run.

Для каждого материала обязателен `source_verifications` в approved JSON: для
каждой опубликованной ссылки — результат её открытия (HTTP 200, итоговый URL,
время проверки) и дословная цитата, подтверждающая ключевой тезис поста.
Перед отправкой Windows повторно открывает ссылки и сверяет цитаты. Любая
ошибка открытия, другой итоговый URL или отсутствие цитаты блокируют весь
выпуск до Telegram.


Логи: `runtime-logs\*.log`. Результат: `News Claude\pipeline\digest\YYYY-MM-DD_digest.md`. Детальное покрытие: `News Claude\pipeline\raw\YYYY-MM-DD\collection_manifest.json`. Статус ok означает получение данных, а не проверку фактов. failed означает сбой; manual — источник требует ручного добора. Нельзя отчитываться об успешном сборе только по коду завершения процесса: проверить покрытие, число кандидатов и даты. Пока идёт новый прогон, портал может показывать предыдущий манифест.

## Telegram — отдельная новая сессия

Авторизован и проверен `@academy_of_beps`; доступ к группе «Новости Академии Чат» подтверждён без отправки сообщения.

- Python: `.venv\Scripts\python.exe` (использовать этот путь; системная команда python указывает на сломанную установку).
- Сессия: `.telegram_auth\academy_news_windows.session`.
- Настройки: `.telegram_auth\.env`.
- Разрешённый редакционный чат: `-1004472011991`.

Старые `session.session` и `academy_news_new.session` не использовать на этой машине. Не копировать новую сессию обратно на другой компьютер. Никогда не выводить токены, API hash и содержимое сессии. Новый вход повторно не нужен.

Без отправки сообщений проверить доступ:

```powershell
.\.venv\Scripts\python.exe -X utf8 .\verify-telegram.py
```

Перед выпуском прочитать `Инструкции Налоги\МАНУАЛ_ПОДГОТОВКИ_НОВОСТЕЙ_CODEX.md`, `Инструкции Налоги\НОВОСТИ_ПРОТОКОЛ.md`, корневой `ОПУБЛИКОВАННЫЕ_НОВОСТИ.md` и актуальные редакционные указания. Название CODEX в старом мануале обозначает прежнего исполнителя; после переноса его редакционные требования выполняет Antigravity. Устаревшие абсолютные macOS-пути заменяются локальными путями из этой инструкции. На Windows права защищены ACL; межпроцессная блокировка реализована через msvcrt, lsof не требуется.

Существующая схема: начало работы в 08:00, 12:00, 16:00, дедлайны 09:00, 13:00, 17:00. Antigravity должен проверить своё расписание и настроить эти три редакционных цикла. Проверка чата — внутри выпусков; отдельный polling/listener не создавать. Автоматическую настройку внутренних будильников Antigravity со стороны Codex подтвердить нельзя.

В каждом выпуске — 10 проверенных уникальных налоговых материалов по существующему протоколу, с изображениями и обязательными хештегами. Если качественных материалов недостаточно, продолжать поиск и честно указать дефицит. Старые approved-файлы не переотправлять. В основной канал и другие соцсети без отдельного указания не публиковать. Новости НейроЮриста в текущий перенос запуска не входят.

## Исправления переноса

- Команда hooks.json плагина Antigravity исправлена без удаления плагина; резервная копия рядом: hooks.json.backup-20260907. При сохранении старой ошибки перезапустить Antigravity для перечитывания конфигурации.
- Создана отдельная среда Python 3.14 и установлены зависимости; версии в requirements-windows.lock.txt.
- В среде проекта включено системное хранилище сертификатов Windows через truststore и `.venv\Lib\site-packages\sitecustomize.py`. Проверка сертификатов не отключена. При пересоздании среды сохранить этот файл; pip использует собственную настройку truststore.
- Исправлены повреждённые русские строки в шести Python-файлах, включая фильтры налоговых новостей.
- На локальном Windows SQLite работает напрямую с блокировкой и synchronous=FULL; старый механизм общей временной копии мог приводить к потере изменений при одновременной работе портала и сборщика.
- Исправлены UTF-8 при фоновом запуске портала, проверка аккаунта при чтении комментариев и вызов get_messages.

RAS требует доступного браузера CDP на 127.0.0.1:9222; наличие восстановленного модуля само по себе не гарантирует доступ к сайту. FD требует ручного браузерного сбора. По остальным сбоям смотреть свежий манифест, а не старые отчёты. Отсутствующие тестовые fixtures и тесты macOS не считать успешной проверкой Windows.
