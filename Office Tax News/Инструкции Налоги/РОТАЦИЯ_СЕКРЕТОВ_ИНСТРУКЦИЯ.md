# Ротация секретов Postiz — пошагово (Фаза 0.1)

Эти секреты лежали открытым текстом в трёх `docker-compose` в синхронизируемой
папке. Файлы уже санитизированы (значения вынесены в gitignored `postiz/.env`),
но **сами значения остаются скомпрометированными, пока не ротированы**. Ниже —
ручные действия владельца. Новые значения вписывать в `postiz/.env` (и, если
используется, `postiz/cloud-migration/.env`), значения в чат/журналы не копировать.

Затронутые ключи: `JWT_SECRET`, `YOUTUBE_CLIENT_ID` / `YOUTUBE_CLIENT_SECRET`,
API-ключ организации Postiz (из `postiz-db.dump`).

---

## 1. YouTube OAuth (Google Cloud Console)

1. Открыть https://console.cloud.google.com/ → проект, к которому привязан
   OAuth-клиент (client_id оканчивается на `…apps.googleusercontent.com`).
2. **APIs & Services → Credentials**.
3. Найти OAuth 2.0 Client ID, использованный для Postiz/YouTube.
4. Кнопка **Reset Secret** (сбросить секрет) — сгенерируется новый
   `YOUTUBE_CLIENT_SECRET`. Старый немедленно перестанет работать.
   - Если клиент мог утечь целиком — вместо сброса создать **новый** OAuth Client
     ID и удалить старый; тогда сменится и `YOUTUBE_CLIENT_ID`.
5. Новое значение вписать в `postiz/.env` (`YOUTUBE_CLIENT_SECRET=…`,
   при необходимости `YOUTUBE_CLIENT_ID=…`).
6. Проверить, что redirect URI в клиенте соответствует адресу Postiz.

## 2. JWT_SECRET (Postiz)

1. Сгенерировать новую случайную строку (48 байт hex), например в терминале:
   `openssl rand -hex 48`
2. Вписать в `postiz/.env` как `JWT_SECRET=…`.
3. Следствие: все текущие сессии Postiz инвалидируются — потребуется повторный
   вход. Это ожидаемо и допустимо.

## 3. API-ключ организации Postiz (из дампа)

Дамп `postiz-db.dump` содержал `apiKey` организации (публичный API-ключ Postiz).
1. Запустить Postiz (`docker compose up -d` из `postiz/`, `.env` уже на месте).
2. В UI: **Settings → Developers → Public API** — сгенерировать/ротировать ключ
   (revoke старый, создать новый).
3. Новый ключ понадобится для Фазы 3 — положить в `News Claude/.env.postiz`
   (файл пока не существует; создать при старте Фазы 3).

## 4. После ротации

1. Перезапустить Postiz, чтобы подхватить новый `.env`:
   `cd postiz && docker compose up -d`.
2. Удалить карантинную папку `postiz/cloud-migration/_TO_DELETE_секреты/`
   (в ней старый дамп с прежним apiKey) и очистить её из облачной синхронизации.
3. Погасить GCP-инстанс `34.32.148.16` (на нём тот же старый JWT_SECRET).
4. Сообщить Claude «ротация выполнена» — при желании прогоним повторный
   secret-скан для подтверждения чистоты.
