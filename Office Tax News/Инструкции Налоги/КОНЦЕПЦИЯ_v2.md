# Новостной конвейер v2 — концепция (2026-07-02)

Цель: ежедневно в 09:00 — подборка до 15 новостей из источников (rechtspraak.nl,
ras.arbitr.ru, garant.ru, regfollower.com, fd.nl, taxlive.nl, taxence.nl);
Роустам назначает каналы («3 → tg, 5 → vk», можно с правками) — конвейер
публикует через Postiz (localhost:4007, доступ через Claude in Chrome).

Принцип (по образцу пайплайна «Ирина 21»): детерминированный код для
парсинга/скоринга/дедупа/состояния; Claude — только транспорт (web_fetch,
Chrome) и редактор текстов. Ошибка одного источника не валит прогон.

## Поток данных

```
09:00 (расписание)
  A. FETCH   web_fetch по endpoints из config/sources.yaml
             → pipeline/raw/{дата}/{source}_{n}.{xml|html}
  B. PARSE   scripts/parse_feeds.py  → pipeline/inbox/{дата}_items.jsonl
  C. SELECT  scripts/select_news.py  → top-15 (скоринг по topics.yaml,
             дедуп по state.sqlite: URL/ECLI + похожесть заголовков)
  D. DIGEST  scripts/make_digest.py → скелет; Claude дописывает суть 2–3
             предложения (только из источника) → pipeline/digest/{дата}_digest.md
             → сообщение в чат: нумерованный список + предложенные каналы
Вы отвечаете:  «3 → tg; 5 → vk; 7 → tg+vk, убери первый абзац»
  E. DRAFT   черновики по форматам channels.yaml → на подтверждение
  F. PUBLISH после «да» по посту: Chrome → localhost:4007
             POST /api/public/v1/posts (ключ из .env.postiz)
  G. LOG     state.sqlite + log/pipeline_log.md + pipeline/published/
```

## Компоненты

- config/sources.yaml — переписывается: только проверенные endpoints (что
  реально отдаёт web_fetch), способ парсинга, вес источника, окно свежести.
- scripts/ (Python 3, stdlib): parse_feeds.py, select_news.py, make_digest.py,
  db.py (SQLite: items, runs, published). Скоринг: приоритет темы (P1=3,
  P2=2, P3=1, по keywords_ru/nl/en в заголовке+аннотации) × вес источника +
  свежесть; судебное решение по теме P1 проходит всегда; порог отсечения,
  потом кап 15.
- Postiz: id каналов подтягиваются GET /api/public/v1/integrations и
  вписываются в config/postiz.yaml. Публикация — POST из вкладки
  localhost:4007 (same-origin fetch через Chrome). LinkedIn — всегда draft.
- ras.arbitr.ru: антибот; плановый утренний прогон пробует fetch, при отказе
  помечает «добрать через Chrome» — добор в сессии публикации, когда Chrome
  открыт.
- fd.nl: только открытые анонсы (paywall).

## Границы

- Публикация только после явного «да» по каждому посту.
- telegram_chats, site, email — вне Postiz (как в v1).
- Факты только из источника; ссылка на первоисточник обязательна;
  дисклеймер для судебных разборов.
