# Конструктор плана публикаций — концепция (v1, черновик до внедрения)

Статус: концепция согласовывается. Ничего в PROCESS.md и задаче 09:02 пока не
меняется. Живой пример виджета показан в чате 2026-07-07.

## 1. Идея в одну строку

Все необработанные материалы (новости + суды ras.arbitr.ru) лежат в одной
очереди; раз в день Claude показывает её интерактивным виджетом с галочками;
Роустам собирает план кликами; одна кнопка превращает выбор в команду; дальше
существующий конвейер: разметка → черновики → подтверждение → Postiz с
отложенным временем. Календарь Postiz = готовый визуальный план публикаций.

## 2. Что меняется в схеме потока

Было:

```
FETCH → PARSE → SELECT → DIGEST(текст) → [ответ «3 → tg; 5 → vk»] → DRAFT → PUBLISH → LOG
```

Станет:

```
FETCH → PARSE → SELECT → QUEUE → ВИДЖЕТ(галочки) → ПЛАН(одна команда) → DRAFT → PUBLISH(Postiz + время) → LOG
```

Меняются только два звена: DIGEST-текст заменяется виджетом, а ответ вручную —
кнопкой «Собрать план». Ядро (parse/select/mark/дедуп) не трогаем.

## 3. Очередь (QUEUE)

- Очередь = все пункты шортлистов за последние 7 дней со статусом «отобрано»
  (ещё не размечено, не опубликовано, не пропущено). Не только сегодняшние —
  необработанное копится и висит перед глазами, пока не решено.
- Новый скрипт `scripts/queue.py list` собирает эти пункты в JSON для виджета.
  Статусы уже есть в конвейере (mark.py assign / published / skip) — queue.py
  их только читает, ничего нового не изобретаем.
- Строка очереди: заголовок (ссылкой на первоисточник), источник, страна, дата,
  оценка; для судов — пометка «суд · ru_ras».

## 4. Экран конструктора (виджет в чате)

Каждая строка:

- **Чипы каналов** — ТГ-канал, ТГ-чаты, VK, LinkedIn, Сайт, Email-дайджест.
  Формат отдельно НЕ выбирается: канал = формат (зашито в channels.yaml:
  ТГ-канал — пост 500–1500 знаков, Сайт — лонгрид-разбор, Email — блок
  недельного дайджеста и т.д.).
- **Слот времени** — сегодня 10:00 / 13:00 / 17:00 / завтра 10:00
  (набор слотов уточним при внедрении).
- Подсказка: чипы предвыбраны по suggested_channels из шортлиста — часто
  достаточно снять/добавить пару галочек.

Правила:

- Нет галочек = пункт остаётся в очереди (завтра снова в виджете). Явное
  «пропустить навсегда» — отдельной кнопкой строки (mark.py skip).
- Судебные строки при генерации черновика автоматически получают дисклеймер
  «не является налоговой консультацией» (правило уже в channels.yaml).
- Правки текста («в посте про X подчеркни Y») — обычным сообщением после
  кнопки; учитываются на этапе черновиков, как сейчас.

## 5. Команда-план (контракт кнопки)

Кнопка «Собрать план» отправляет в чат одну команду фиксированного формата:

```
План публикаций 2026-07-07: 1 → telegram_channel @ сегодня 13:00;
4 → telegram_channel,site @ завтра 10:00. Остальные пункты пропустить.
```

Claude маппит её на существующие инструменты:

- `python3 scripts/mark.py assign --date {дата} --map "1:telegram_channel;4:telegram_channel,site"`
- слоты времени сохраняются до этапа публикации и уходят в Postiz полем
  запланированной даты.

## 6. Стыковка с судами ras.arbitr.ru

Суды — не отдельный процесс, а источник в том же конвейере:

- `ru_ras` собирается ДО SELECT через Chrome (один аккуратный поиск в «Банке
  решений», без частых прямых POST — иначе 451/капча). Уже описано в
  PROCESS.md §2a.
- Новые решения дедуплицируются по номеру дела/URL в news_state.sqlite и
  попадают в тот же шортлист → те же строки конструктора с пометкой «суд».
- Если Chrome в 09:02 недоступен — виджет показывает плашку «суды не добраны»,
  добор при первом заходе в чат; строки судов дозаписываются в очередь.
- Архивный проект 54.1 (папка arbitr.ru, массовая выгрузка PDF) — отдельная
  история. Опция на потом: раз в неделю отбирать из свежескачанного 1–2
  решения и класть в ту же очередь как кандидатов на «Сайт (разбор)».

## 7. Стыковка с Postiz

Postiz — исполнитель плана, второй дашборд не нужен:

- Публикация по scripts/postiz_publish.md: Chrome → вкладка localhost:4007 →
  same-origin `POST /api/public/v1/posts`, ключ из .env.postiz (без Bearer).
- Новое: в тело запроса подставляется дата/время из слота → пост уходит
  отложенным. Сетка всех запланированных постов видна в календаре Postiz.
- LinkedIn — всегда draft. Каждый пост отправляется только после явного «да»
  в чате (правило не меняется).
- После ответа Postiz: `mark.py published` + строка в log/pipeline_log.md —
  пункт исчезает из очереди.

## 8. Сквозной пример (на материале 07.07)

1. 09:02 — прогон собрал 3 новости (taxlive ×2, regfollower) + 1 решение
   ru_ras. Виджет: 4 строки, у новостей предвыбран ТГ-канал.
2. Роустам кликает: №1 → ТГ-канал @ сегодня 13:00; №4 (суд) → ТГ-канал +
   Сайт @ завтра 10:00. №2 и №3 не трогает. Жмёт «Собрать план».
3. В чат уходит команда-план. Claude: mark.py assign; №2–3 остаются в очереди
   на завтра.
4. Claude показывает черновик поста №1 (формат ТГ-канала) — «да»; черновик
   поста №4 для ТГ и лонгрид для сайта с дисклеймером — «да».
5. Chrome → Postiz: №1 запланирован на 13:00 сегодня, №4 — на 10:00 завтра
   (два канала). В календаре Postiz видна вся сетка.
6. mark.py published + лог. Завтра в 09:02 виджет: вчерашние №2–3 сверху +
   новое за день.

## 9. Что пилим при внедрении (по команде «внедряй»)

1. `scripts/queue.py` — очередь необработанного за 7 дней (читает shortlist +
   статусы mark.py).
2. PROCESS.md §2d и §3 — виджет вместо текстового дайджеста, контракт
   команды-плана, слоты времени.
3. Промт задачи `academy-news-daily` — в конце прогона рендерить виджет из
   queue.py.
4. postiz_publish.md — добавить поле запланированной даты из слота.

Идеи на v2 (не сейчас): кнопка «показать черновик» прямо в строке виджета;
автосборка недельного email-дайджеста из накопленных галочек «Email»;
недельная рубрика из архива 54.1.
