# Контент-конвейер для Claude Cowork: набор промтов

Задача: из регулярного потока входящей информации (суды NL/RU, подписные издания, YouTube, СМИ, поиск) делать аналитику и публикации в Telegram, VK, LinkedIn, на сайт и в email-рассылку.

Режим: гибрид — сбор и отбор по расписанию, утверждение и публикация вручную.

## Архитектура

```
ИСТОЧНИКИ ──► ПРОМТ 1: СБОР ──► pipeline/inbox/
(ежедневно, авто)                    │
                                     ▼
              ПРОМТ 2: ОТБОР ──► pipeline/shortlist/
              (авто, сразу после сбора)
                                     │
                                     ▼
              ПРОМТ 3: ЧЕРНОВИКИ ──► pipeline/drafts/
              (авто)                 │
                                     ▼
              ПРОМТ 4: УТВЕРЖДЕНИЕ И ПУБЛИКАЦИЯ (вручную, вы)
                                     │
                                     ▼
              pipeline/published/ + log/pipeline_log.md

              ПРОМТ 5: НЕДЕЛЬНАЯ АНАЛИТИКА (пятница, авто)
```

Ключевой принцип: каждый этап читает файлы предыдущего и пишет файлы для следующего. Это позволяет запускать этапы независимо, отлаживать по одному и не терять данные между сессиями.

## Структура папок (создаётся ПРОМТОМ 0)

```
Новости Академии/
├── config/
│   ├── sources.yaml     # все источники и способ доступа к каждому
│   ├── topics.yaml      # целевые темы, ключевые слова, приоритеты
│   └── channels.yaml    # каналы, форматы, лимиты, тон, язык
├── pipeline/
│   ├── inbox/           # сырой сбор: 2026-07-02_inbox.md
│   ├── shortlist/       # отобранное со скорингом
│   ├── drafts/          # черновики по каналам
│   ├── approved/        # утверждено вами
│   └── published/       # опубликовано, со ссылками
└── log/
    └── pipeline_log.md  # журнал: URL, дата, статус (для дедупликации)
```

## ПРОМТ 0 — Первичная настройка (запустить один раз)

```
Настрой контент-конвейер в папке «Новости Академии/News Claude».

1. Создай структуру папок: config/, pipeline/inbox/, pipeline/shortlist/,
   pipeline/drafts/, pipeline/approved/, pipeline/published/, log/.

2. Создай config/sources.yaml по этому шаблону (уточни у меня список перед сохранением):

   sources:
     - id: nl_rechtspraak
       name: Решения судов Нидерландов
       type: court_nl
       access: web
       url: https://uitspraken.rechtspraak.nl
       how: >
         Искать решения за последние 2 дня по запросам из topics.yaml
         (например "dubbele belasting", "belastingverdrag", "woonplaats",
         "vaste inrichting", "dividendbelasting"). Приоритет: Hoge Raad,
         затем gerechtshoven. Использовать открытый поиск/Open Data API
         data.rechtspraak.nl.
     - id: ru_arbitr
       name: Российские арбитражные суды
       type: court_ru
       access: web_or_chrome
       url: https://kad.arbitr.ru + https://sudact.ru
       how: >
         Новые акты по ключевым словам: "двойное налогообложение",
         "соглашение об избежании", "фактическое право на доход",
         "налоговый резидент". Если сайт не отдаёт контент по fetch —
         читать через Claude in Chrome.
     - id: nl_media
       name: Голландские СМИ и налоговые издания
       type: media
       access: web
       urls: [fd.nl, nos.nl, taxence.nl, taxlive.nl, accountancyvanmorgen.nl]
       how: Заголовки и налоговые материалы за последние 24 часа.
     - id: subscriptions
       name: Издания по подписке (с логином)
       type: paywall
       access: chrome_login
       urls: [<укажу список>]
       how: >
         Я захожу в аккаунт в Chrome заранее; Claude in Chrome открывает
         раздел новых материалов и читает тексты со страницы.
     - id: youtube
       name: YouTube-каналы и видео
       type: video
       access: web_or_chrome
       channels: [<укажу список>]
       how: >
         Проверить новые видео за неделю; получить транскрипт (субтитры)
         и сделать конспект с таймкодами ключевых тезисов.
     - id: websearch
       name: Тематический поиск в интернете
       type: search
       access: websearch
       how: >
         2–3 поисковых запроса по темам с высшим приоритетом из topics.yaml,
         фильтр по свежести (последние 3 дня).

3. Создай config/topics.yaml:

   topics:
     - id: dta
       name: Избежание двойного налогообложения
       priority: 1
       keywords_ru: [двойное налогообложение, СИДН, фактическое право на доход, налоговое резидентство]
       keywords_nl: [dubbele belasting, belastingverdrag, woonplaats, verdragstoepassing]
       keywords_en: [double taxation, tax treaty, beneficial owner, MLI, BEPS]
     - id: nl_ru
       name: Налоговые отношения NL–RU, приостановка СИДН, санкции
       priority: 1
       keywords_ru: [приостановка соглашения, СИДН Нидерланды, выплаты за рубеж]
     - id: substance_migration
       name: Сабстенс, редомициляция, переезд бизнеса и людей
       priority: 2
       keywords: [substance, exit tax, 30% ruling, emigratie, редомициляция]
     # добавь мои темы после уточнения

4. Создай config/channels.yaml:

   channels:
     - id: telegram_channel
       format: пост 500–1500 знаков, заголовок жирным, 1 ссылка на источник, без хэштегов
       language: ru
       tone: экспертно, без канцелярита, вывод в конце
     - id: telegram_chats
       note: рассылка в чаты через мой антиспам-контакт; текст короче, 300–600 знаков, без ссылок-приманок
       language: ru
     - id: vk
       format: как telegram_channel, но допускается 2–3 хэштега; процесс публикации уже налажен
       language: ru
     - id: linkedin
       format: пост 800–1800 знаков, хук в первой строке, 3–5 хэштегов
       language: en или nl по теме
     - id: site
       format: лонгрид 800–1200 слов, H2-подзаголовки, цитаты из решения, вывод для практики
       language: ru (или en для международной аудитории)
     - id: email
       format: блок дайджеста 3–5 предложений на материал; собирается еженедельно
       language: ru

   rules:
     - Факты только из источника, ничего не додумывать; цифры и даты сверять.
     - Всегда ссылка на первоисточник (ECLI, номер дела, URL).
     - Дисклеймер для судебных разборов: «не является налоговой консультацией».
     - Стиль: писать как практикующий налоговый юрист, а не как новостной агрегатор.

5. Создай пустой log/pipeline_log.md с таблицей: дата | источник | URL | заголовок | статус (собрано/отобрано/черновик/опубликовано:канал).

Перед сохранением конфигов задай мне вопросы по спискам источников, тем и каналов.
```

## ПРОМТ 1 — Ежедневный сбор (по расписанию)

```
Ты — сборщик информации контент-конвейера в папке «Новости Академии/News Claude».

1. Прочитай config/sources.yaml, config/topics.yaml и последние 200 строк
   log/pipeline_log.md (для дедупликации по URL).
2. Обойди каждый источник согласно его полю how:
   - access: web / websearch — используй веб-поиск и fetch;
   - access: chrome_login / web_or_chrome — используй Claude in Chrome
     (я уже залогинен); если браузер недоступен, пропусти источник и
     отметь это в отчёте, не останавливай весь сбор;
   - видео — найди транскрипт/субтитры и работай по ним.
3. Ошибка на одном источнике не должна прерывать остальные: зафиксируй
   ошибку и иди дальше.
4. Каждую находку, которой ещё нет в логе, запиши в
   pipeline/inbox/{сегодняшняя дата}_inbox.md в формате:

   ## [ID] Заголовок
   - Источник: … | URL/ECLI: … | Дата материала: …
   - Язык: ru/nl/en
   - Суть (3–5 предложений, факты, суммы, стороны, вывод суда/автора)
   - Темы: (id из topics.yaml)
   - Предв. оценка потенциала: 1–5

5. Допиши все находки в log/pipeline_log.md со статусом «собрано».
6. В конце — короткая сводка: сколько источников обойдено, сколько
   находок, какие источники не сработали.

Ничего не публикуй и не пиши черновиков — только сбор.
```

## ПРОМТ 2 — Отбор и скоринг (авто, сразу после сбора)

```
Ты — редактор-фильтр конвейера в папке «Новости Академии/News Claude».

1. Прочитай сегодняшний файл pipeline/inbox/ и config/topics.yaml.
2. Оцени каждый материал по трём шкалам (1–5):
   - релевантность целевым темам (priority темы повышает вес);
   - новизна (нет ли этого уже в log/pipeline_log.md со статусом
     «отобрано» или «опубликовано»; не пересказ ли старой новости);
   - ценность для аудитории (можно ли извлечь практический вывод:
     «что это значит для клиента/налогоплательщика»).
3. В shortlist проходят материалы с суммой ≥ 11, но не более 5 в день.
   Новое судебное решение по теме priority 1 (например, по избежанию
   двойного налогообложения) проходит всегда.
4. Запиши pipeline/shortlist/{дата}_shortlist.md: для каждого материала —
   оценки, одно предложение «почему берём», предлагаемый угол подачи
   и целевые каналы из channels.yaml.
5. Материал с пометкой «горячее» (решение Hoge Raad, громкое дело,
   изменение закона) вынеси первым блоком.
6. Обнови статусы в log/pipeline_log.md на «отобрано».
```

## ПРОМТ 3 — Генерация черновиков (авто)

```
Ты — автор публикаций налоговой практики. Папка «Новости Академии/News Claude» (рабочий корень).

1. Прочитай свежий pipeline/shortlist/ и config/channels.yaml
   (форматы, тон, правила).
2. Для каждого материала создай черновики под каналы, указанные в
   shortlist. Для судебных решений структура: факты дела → позиция
   суда → почему это важно → практический вывод. Если материал на
   nl/en — сначала точный смысловой перевод, потом адаптация.
3. Один файл на материал: pipeline/drafts/{дата}_{ID}_{тема}.md,
   внутри — секции по каналам (## telegram_channel, ## vk,
   ## linkedin, ## site, ## email) и ссылка на первоисточник.
4. Соблюдай правила из channels.yaml: лимиты знаков, язык, дисклеймер,
   никаких фактов не из источника. Если в источнике не хватает данных
   для утверждения — пометь [ПРОВЕРИТЬ].
5. В конце выведи список созданных черновиков со статусом
   «ожидает утверждения» и обнови лог.
```

## ПРОМТ 4 — Утверждение и публикация (запускаете вручную)

```
Режим публикации. Папка «Новости Академии/News Claude» (рабочий корень).

1. Покажи список черновиков из pipeline/drafts/ со статусом
   «ожидает утверждения»: заголовок, каналы, первые 2 строки.
2. По каждому спроси решение: утвердить / править / отклонить.
   Правки вноси в файл сразу.
3. Утверждённые перенеси в pipeline/approved/ и подготовь к публикации:
   - telegram_channel и telegram_chats: финальный текст отдельным
     блоком для копирования; текст для чатов — версия под рассылку
     через мой антиспам-контакт;
   - vk: текст под мой налаженный VK-процесс;
   - linkedin: финальный пост (en/nl);
   - site: готовый лонгрид отдельным .md (или .docx по запросу);
   - email: блок добавь в накопительный файл
     pipeline/drafts/email_digest_{неделя}.md.
4. Автопостинг через Postiz (config/postiz.yaml). Только после моего
   явного «да» по каждому посту:
   - проверь, что заданы POSTIZ_API_URL и POSTIZ_API_KEY и что канал
     доступен (`postiz integrations:list`); если id в channel_map пустые —
     возьми их из integrations:list и впиши;
   - если Postiz недоступен (запуск в песочнице, где localhost:4007 не
     виден) — не пытайся постить, выдай готовые команды postiz для запуска
     на моей машине и финальные тексты для ручной вставки;
   - telegram_channel/vk: `postiz posts:create -c "<текст>" -s "<ISO-дата>"
     -i "<id>"` (или -t draft). Медиа — сначала `postiz upload`, затем -m;
   - linkedin: по умолчанию -t draft;
   - telegram_chats, site, email — НЕ через Postiz (чаты — антиспам-бот,
     сайт и рассылка — отдельно).
5. Опубликованное/запланированное перенеси в pipeline/published/, в лог
   запиши «опубликовано: канал, дата, ссылка/post-id».
```

## ПРОМТ 5 — Недельная аналитика и дайджест (пятница, авто)

```
Ты — аналитик конвейера. Папка «Новости Академии/News Claude» (рабочий корень).

1. Прочитай shortlist и published за последние 7 дней и лог.
2. Подготовь два документа:
   а) pipeline/drafts/{дата}_analytics.md — внутренняя записка:
      тренды недели по темам; что опубликовано и куда; какие темы
      priority 1 остались без публикаций (пробелы); 5 идей контента
      на следующую неделю (включая идеи лонгридов из накопившихся
      судебных решений);
   б) финальный email-дайджест недели из накопленного
      email_digest файла: вступление 2–3 предложения, 3–5 блоков,
      выводы — в pipeline/drafts/{дата}_email_final.md.
3. Ничего не отправляй — оба документа на моё утверждение.
```

## Настройка расписаний (сказать Cowork один раз)

- «Каждый будний день в 08:00 выполни ПРОМТ 1 из файла Контент-конвейер_промты_Cowork.md, затем сразу ПРОМТ 2 и ПРОМТ 3».
- «Каждую пятницу в 15:00 выполни ПРОМТ 5».
- ПРОМТ 4 не планировать — запускается вами вручную фразой «режим публикации».

Примечание: в запланированных запусках Chrome-источники (подписки, часть YouTube) могут быть недоступны — конвейер их пропустит и отметит; их можно добирать при ручном запуске ПРОМТА 1 днём.

## Практические приёмы

Подписные издания: Cowork не хранит пароли. Один раз войдите в аккаунты в Chrome — Claude in Chrome читает страницы уже в вашей сессии. Fetch для платного контента работать не будет, это нормально.

YouTube и видеофайлы: основной путь — транскрипт/субтитры, по ним конспект с таймкодами. Локальные видеофайлы кладите в папку — Cowork извлечёт звук и обработает.

Telegram-чаты: конвейер готовит тексты (версия для чатов короче и без агрессивных ссылок), отправка — через ваш существующий антиспам-контакт/бота. Автопостинг в канал возможен через Postiz (поддерживает Telegram и VK) или ваши сценарии Make — подключается на этапе ПРОМТА 4.

Дедупликация: единственный источник правды — log/pipeline_log.md. Не чистите его; при разрастании попросите Cowork заархивировать старые записи.

Отладка: первые 3–5 дней запускайте ПРОМТЫ 1–3 вручную и правьте конфиги (topics.yaml — самое важное: качество отбора зависит от ключевых слов). Потом переводите на расписание.
