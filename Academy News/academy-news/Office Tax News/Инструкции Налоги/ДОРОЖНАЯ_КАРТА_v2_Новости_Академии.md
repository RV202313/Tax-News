## 0. Резюме: что изменилось по сравнению с анализом Opus

Анализ Opus в целом верен по списку симптомов, но аудит показал **три системных факта, которые меняют план**:

1. **Конвейер Клода почти не влияет на публикации.** По `ЖУРНАЛ_ПРОГОНОВ_CODEX.md` за 10 выпусков (14–17.07): из ~30 кандидатов дайджеста Клода в публикации вошёл **1** (выпуск 16.07 09:00). ~99% контента Codex находит сам. Ремонт источников имеет смысл только если дайджест станет достаточно богатым, чтобы Codex реально из него брал. Поэтому в карту добавлен **KPI: доля материалов выпуска, пришедших из конвейера** — без него Фаза 2 может «формально» завершиться, ничего не изменив.

2. **Первопричина большинства сбоев источников — транспорт web_fetch, а не сайты.** Пять «квирков», описанных как свойства источников (`[binary data]` на XML/RSS, схлопывание `date=A&date=B`, «неработающий» `subject=belastingrecht`, кэш-снапшоты regfollower/taxlive/garant, потеря кириллицы windows-1251), — артефакты одного инструмента. Живые проверки 2026-07-17 подтвердили: **фильтр `subject` (belastingrecht) в Open Data rechtspraak РАБОТАЕТ**, если `#` в URI закодирован как `%23` (см. §5.1) — прежний вывод «0 результатов во всех вариантах» был ошибкой кодирования URL в web_fetch. Лечение — не обходы, а **смена транспорта на прямой HTTP с мака** (bash/python в утренней сессии); web_fetch остаётся запасным.

3. **«Детерминированное ядро по расписанию launchd» — миф.** LaunchAgent `com.academy.news.daily` ни разу не сработал (нет `log/launchd_daily.*.log`), `collect_sources.py`/`daily_run.py` ни разу не запускались в бою (нигде нет ни одного `collection_manifest.json`; поле `sources_ok/failed` в таблице `runs` пусто во всех 14 строках). Боевой сбор делает Cowork-задача: Claude руками web_fetch'ит источники и запускает parse/select/digest через bash. Реальных путей сбора **три** (web_fetch-в-сессии; мёртвый requests-код; ручной Chrome), а не два.

Порядок владельца сохраняется («порядок → источники → публикация»), но в Фазу 0 добавлены **быстрые победы по источникам**: rechtspraak чинится ~за час без всякого рефакторинга, а это прямой приоритет владельца.

### 1.2 Опровергнуто или существенно уточнено

1. **«Расписание — macOS LaunchAgent в 09:00»** — не соответствует реальности (см. Резюме, п. 3). Также устарело «09:02» из памяти проекта: с 14.07 прогон Клода идёт в ~08:00–08:07 CEST (мануал Codex v1.3: «Клод стартует в 08:00, готовность к 09:00»); `runs.started` это подтверждают (06:0x UTC). При этом `pipeline_log.md` продолжает писать «Автопрогон (09:02)» — журналирование врёт, поправить.
2. **«subject=belastingrecht не фильтрует»** (повторено Opus'ом из `sources.yaml`) — **опровергнуто живой проверкой 2026-07-17**: `subject=http%3A%2F%2Fpsi.rechtspraak.nl%2Frechtsgebied%23bestuursrecht_belastingrecht` вернул «Aantal gevonden ECLI's: 4» за 15–16.07 — все четыре чисто налоговые (parkeerbelasting, WOZ, OZB). Причина прежних нулей: web_fetch терял `#…` как фрагмент URL.
3. **«Свести транспорт к предсказуемому» недооценён по объёму.** Все стратегии `parse_html_links` (A–D) заточены под **markdown-вывод web_fetch** (ссылки `[title](url)`, кавычки-эвристики). Прямой HTTP отдаёт живой HTML/XML — парсеры HTML-источников придётся переписать на разбор `<a href>`/RSS (стандартная библиотека, но это отдельная задача Фазы 1, а не «просто поменять транспорт»). Для rechtspraak переписывать не надо: `parse_rechtspraak_atom` regex'ом берёт `<entry>` и работает на сыром Atom XML как есть.
4. **Секреты: масштаб больше.** Тот же `JWT_SECRET` и `YOUTUBE_CLIENT_ID/SECRET` лежат и в **основном** `postiz/docker-compose.yaml`, и в `cloud-migration/docker-compose.local.yaml` (идентичен основному), а не только в cloud-варианте. Зато **git чист**: `postiz/.git` — одиночный клон upstream-репозитория `gitroomhq/postiz-docker-compose` (одна запись в `logs/HEAD`), секреты в историю не коммитились, переписывать историю не нужно — достаточно ротации и выноса в `.env`.
5. **ru_fns тоже сломан** (Opus не заметил): `_fetch_log 2026-07-16` фиксирует провенанс-блок и для nalog.gov.ru; в `state` **ноль** записей ru_fns за всю историю. Фактически стабильно работают только regfollower + taxence + taxlive (+ garant с протухшим кэш-снапшотом 02.07, уже ~15 дней).
6. **«Кэш-снапшоты CDN у regfollower/taxlive/garant»** — почти наверняка кэш самого web_fetch, а не сайтов. Через прямой HTTP проблема должна исчезнуть — проверить в Фазе 1 первым же прогоном (если нет — тогда уже думать про заголовки/CDN).
7. **ВС РФ не требует CDP-обхода:** vsrf.ru отдаёт контент обычному fetch'у (проверено 17.07: главная с новостями июня-2026, разделы пресс-центра и документов доступны; `/press_center/news/` дал 404 — путь надо уточнить по живой структуре сайта). Рецепт Opus «сначала HTTP, при антиботе CDP» верен, но стартовая гипотеза — «прямой HTTP работает».
8. **Минфин под антиботом:** `minfin.gov.ru` вернул 503 на robots.txt (инструментальный fetch отклонён). С мака через curl может работать — проверить; иначе план Б: письма Минфина стабильно дублируются garant/ФНС-агрегаторами.

### 1.3 Найдено дополнительно (у Opus отсутствует)

1. **P0-security шире:** (а) `postiz/cloud-migration/postiz-db.dump` — дамп БД Postiz: содержит **apiKey организации** (64-hex, публичный API-ключ Postiz), e-mail'ы (`radiobepsapp@gmail.com`, `academybeps@carbontis.com`); (б) облачный compose указывает на **GCP-инстанс `34.32.148.16` (sslip.io)** с тем же JWT_SECRET — выяснить, жив ли инстанс, и погасить/ротировать; (в) основной compose публикует Postiz на **`0.0.0.0:4007`** (`"4007:5000"`) — панель видна всей локальной сети; в cloud-варианте уже исправлено на `127.0.0.1`, в основном — нет.
2. **Логическая ошибка в `select_news.py` (суды выпадают из отбора).** Задумано: «судебный источник проходит при любом налоговом матче». Реализация — мёртвый код: ветка `if is_court and any_hit` недостижима (при `any_hit=True` всегда задан `best_priority`). Итог: судебные материалы без совпадения по ключевым словам **молча выбрасываются**. Следствие видно в данных: в `state` за всю историю **ноль** записей `nl_rechtspraak` и `ru_ras` — приоритет №1 владельца ни разу не дошёл даже до дайджеста.
3. **Дубли внутри одного дня не ловятся между источниками:** `is_duplicate` сверяет кандидата только с БД (прошлые дни), внутри текущей пачки нечёткого дедупа нет — одна новость от garant и ФНС может войти в шортлист дважды.

5. **Конфликт за Telethon-сессию.** С 16.07 постоянно работает LaunchAgent-слушатель `com.academybeps.telegram-editorial-listener`, держащий **ту же** `session.session`. Планируемый `collect_telegram.py` (Фаза 2c) на этом же файле сессии → конфликты SQLite-локов Telethon. Нужно решение (см. §5.3): вторая сессия для коллектора / чтение стора существующего монитора Academy Network / пауза слушателя.
6. **Требуемый объём против возможностей конвейера.** Codex нужно 30 проверенных материалов в день; автодайджест даёт 0–5 кандидатов и в «тихие» дни (05, 09, 11, 17.07) законно пуст (всё — дубли вчерашнего). Даже починенный конвейер с текущими 4 источниками не покроет и трети спроса — покрытие дадут именно новые источники Фазы 2 (RU-суды, ВС, Минфин, rechtspraak-фильтр, Telegram-каналы).
7. **Расхождения документации:** `pipeline_log.md` называет себя «единственным источником правды для дедупликации», `PROCESS.md` — называет таковым `state.sqlite`, Codex — свой каталог. Три «источника правды». Плюс `PROCESS.md` §2 всё ещё говорит «09:00», память проекта — «09:02».
8. **`daily_run.py` шлёт ложные тревоги** (если его оживлять): множество `mandatory` включает `ru_ras/ru_minfin/ru_vs/nl_fd`, которые по конфигу всегда `chrome/manual` → предупреждение «Не получены обязательные источники» будет всегда.

## 2. Целевая картина и KPI

Целевая картина Opus (единый наблюдаемый конвейер: RU-суды + NL-суды + Telegram + веб-агрегаторы → редакционный слой → Telegram-редпоток + Postiz-каналы) остаётся в силе, с решениями владельца: Postiz **рядом** с Telethon-потоком, TG в Postiz **не** дублировать, сайты юрфирм — отдельной фазой позже, ВС РФ и Минфин — сразу в Фазе 2.

**KPI (новое, замер в каждом выпуске, колонка в `ЖУРНАЛ_ПРОГОНОВ_CODEX.md` уже есть — «Кандидаты Клода / вошли»):**

- база (14–17.07): **~3%** (1 из ~30 предложенных; ~1% от опубликованного);
- после Фазы 0 (rechtspraak + гейт судов): дайджест содержит NL-судебные материалы ежедневно;
- после Фазы 2: **≥30%** материалов выпусков приходит из конвейера; RU-суды/ВС/Минфин/ФНС и Telegram-лиды в дайджесте ежедневно;
- после Фазы 3: ни одного нового `beps_batch_*.py`; выпуск публикуется движком из JSON; Postiz постит минимум в один не-TG канал.

Вторичные метрики: доля прогонов без сбоя обязательных источников; отставание свежести (дата материала − дата публикации); количество повторов, пойманных общим дедупом.

## 4. Фазовый план

Правила исполнения — как у Opus: фазы по порядку, после каждой — стоп и отчёт владельцу; бой (Codex → Telethon → редчат, 3×10/день) не трогаем до приёмки; каждое изменение — в журналы и в документацию. Роли: **Fable** — концепция/приёмка, **Opus** — код, **Sonnet** — вспомогательное, **Codex** — редакционный слой и всё, что запускается на маке в его сессиях.

### Фаза 0 — Безопасность + быстрые победы (0.5–1.5 дня)

**0.1 Секреты (P0):**
1. Ротировать `JWT_SECRET` (инвалидация сессий Postiz — ок), YouTube-креды в Google Cloud Console, Postiz API-ключ (Settings → Developers).
2. Все три compose перевести на `env_file: .env` (в `.gitignore`); дамп и tgz убрать из папки; порт → `127.0.0.1`.
3. Проверить GCP `34.32.148.16`: жив → погасить (решение владельца: облако откладываем).
4. gitleaks-скан всех подключённых папок; отчёт.

**0.2 Быстрые победы по источникам (безопасно для боя):**
1. **rechtspraak → прямой HTTP.** Новый шаг `scripts/collect_rechtspraak.py` (~50 строк, requests): два запроса `zoeken` с `subject=…%23bestuursrecht_belastingrecht`, `date={сегодня}`, `date={вчера}`, `type=Uitspraak`, `return=DOC`, `max=200`, пауза между запросами; ответ писать как есть в `pipeline/raw/{дата}/nl_rechtspraak_1.txt/_2.txt`. Существующий `parse_rechtspraak_atom` разбирает сырой Atom без правок. В prompt утренней задачи: «вместо web_fetch rechtspraak выполни `python3 scripts/collect_rechtspraak.py --date {дата}`».
2. **Гейт судов в `select_news.py`:** добавить в `sources.yaml` флаг `prefiltered: true` для `nl_rechtspraak` (фильтр по теме уже сделал сервер) и в `select_news` пропускать такие источники при отсутствии матча тем с дефолтным приоритетом 2 (пометка topic=`nl_fiscaal`). Убирает мёртвый код и открывает судам дорогу в шортлист.
3. **ru_fns:** попробовать тем же способом (requests в `collect_rechtspraak.py` переименовать в `collect_http.py` с параметром источника) — но включать в prompt только после того, как в Фазе 1 появится HTML-парсер (иначе сырой HTML не распарсится текущими стратегиями).
